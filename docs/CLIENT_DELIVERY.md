# DINOv3-SAT蒸馏YOLO11m遥感检测项目交付方案

版本：1.0

交付角色：乙方

目标平台：单卡RTX 3090/4090/4090D服务器

目标任务：25细类遥感目标检测，按船、飞机、车辆三大组执行比赛评估，并支持10000×10000大图滑窗推理。

## 1. 交付目标

乙方交付的不是一个无法解释来源的单一权重，而是一套能在新服务器从零复现、能在训练中断后完整恢复、能根据阶段结果自动停止或晋级的训练系统。

系统必须产出以下结论之一：

1. FAH-KD在匹配数据、初始化和训练预算下稳定超过C0，进入最终长训；
2. 只有数据课程或困难样本重放有效，DINOv3无稳定增益，最终采用纯YOLO方案；
3. 当前数据或教师不足以支持蒸馏，流程明确停止并给出失败证据。

三种结论均属于有效项目结果。不得把数据收益、阈值收益或随机波动包装为DINOv3收益。

## 2. 已知历史结论

旧项目已经证明：

- DINOv3教师、P3/P4/P5缓存、特征投影和RoI KL接线能够真实工作；
- 早期静默失效、缓存未命中、hook无梯度、NaN/Inf、AOT donated buffer和续训校准状态问题已经定位并修复；
- 旧40轮结果中，F/K/FK没有稳定超过原始YOLO11m基线；
- 旧V5收益主要来自困难样本重放，而不是DINOv3；
- 飞机性能接近饱和，船和车辆是主要短板；
- 车辆在IoU=0.35时仍有大量背景误报，问题不能通过降低匹配IoU掩盖。

因此新项目不再无界搜索普通F/K/FK权重，而是先更新数据证据，再比较Global-KD和失效感知层级KD。

## 3. 数据设计

### 3.1 数据来源

| 来源 | 数量 | 主用途 |
|---|---:|---|
| 官方数据 | 4481 | TRAIN/VAL/密封TEST |
| 新增数据 | 2218 | TRAIN补充，默认不进入主VAL/TEST |

### 3.2 划分原则

官方数据按不可拆分`cluster_id`执行约70/15/15分组划分；新增数据默认全部进入TRAIN。

`cluster_id`必须合并：

- 同一卫星产品；
- 同一原始大图的不同裁片；
- 内容重叠裁片；
- pHash近重复图；
- 同一目标的不同导出版本。

如果新增图与官方图属于同一簇，该官方簇强制进入TRAIN，不能进入VAL/TEST。

### 3.3 防泄漏门槛

- cluster跨集合数量必须为0；
- 完全相同图像SHA256跨集合数量必须为0；
- VAL/TEST的新增图数量必须为0；
- TEST在最终候选和阈值冻结前不得运行；
- TRAIN OOF每张图必须由没有见过其场景簇的模型预测。

### 3.4 数据版本

本项目使用`scene811_v2`。图像、标签、来源、场景簇或划分发生任何变化，都必须升级数据ID并重建：

- YOLO基线；
- DINO教师；
- 教师缓存；
- OOF模型；
- 困难样本清单；
- 最终模型。

## 4. 模型与创新设计

### 4.1 部署学生

- YOLO11m；
- 输入640作为第一阶段主设置；
- 最终部署约20M参数；
- DINOv3不参与推理。

### 4.2 语义教师

- DINOv3 ViT-L/16 SAT493M预训练权重；
- 冻结DINO主干；
- 训练期FPN和RoI分类头；
- 缓存P3/P4/P5和25类RoI logits；
- 教师置信度、熵和正确性参与可靠性门控。

### 4.3 Global-KD参照

Global-KD对所有GT统一执行：

- 多尺度特征蒸馏；
- RoI分类KL；
- 固定共享梯度预算。

它是传统方法参照，不是最终创新声明。

### 4.4 FAH-KD核心候选

FAH-KD由两个相互关联的部分组成。

第一部分是OOF失效感知路由：

| OOF失效 | 特征分支 | 语义分支 |
|---|---:|---:|
| detected | 极弱 | 极弱 |
| low_confidence | 强 | 强 |
| no_candidate | 最强 | 中等 |
| localization | 弱 | 弱 |
| nms_suppressed | 强 | 中等 |
| wrong_group | 中等 | 最强 |

第二部分是25→3层级KL：

\[
L_{hier}=0.6L_{coarse}+0.4L_{fine\mid coarse}
\]

- `L_coarse`约束船/飞机/车辆三组概率；
- `L_fine|coarse`只在GT所属大组内部传递细类关系；
- 教师只需粗类正确即可参与，但仍受置信度和熵门控；
- 飞机分支预算降低，避免饱和飞机支配梯度；
- 船和车辆获得更高目标权重。

### 4.5 梯度控制

所有辅助损失不直接使用裸系数相加，而是通过共享YOLO特征上的梯度范数校准：

- feature目标比例：0.03；
- classification目标比例：0.005；
- 记录检测/F、检测/K和F/K余弦；
- NaN/Inf、分支连续为0、投影层无梯度、RoI头无梯度时立即停止；
- 健康检查不更新参数、不改变BatchNorm状态。

### 4.6 大图阶段

跨窗一致性和滑窗参数只在小图候选冻结后进入。第一版先验证部署滑窗：

- 800/480；
- 1024/640；
- 必要时1280/800。

若能恢复真实原始大图和裁片坐标，再增加同目标跨窗一致性训练；如果没有坐标证据，不把模拟裁剪宣称为真实跨窗创新。

## 5. 实验矩阵

### 5.1 必做

| 编号 | 模型 | 目的 |
|---|---|---|
| B0-s0 | 新数据YOLO基线seed0 | 主基准 |
| B0-s1 | 新数据YOLO基线seed1 | 基线方差 |
| C0 | B0等预算确定性续训 | KD匹配对照 |
| Global-KD | 普通F+K | 传统KD参照 |
| FAH-KD | 失效路由+层级KL | 核心创新候选 |

### 5.2 只有主候选通过后才做

| 编号 | 模型 | 条件 |
|---|---|---|
| FAH-KD-s1 | 第二seed | seed0通过Gate |
| finalist-C0 | 40～100轮 | 用于最终匹配对照 |
| finalist-FAH | 40～100轮 | 两seed方向一致 |
| replay-C0 | 同一困难样本重放 | 需要分离数据课程收益时 |
| replay-FAH | 相同replay+FAH | 与replay-C0公平比较 |

### 5.3 不默认执行

- MGD；
- 车辆背景辅助头；
- 输入1024长训；
- 多种复杂增强组合；
- 多模型集成。

这些模块只有在错误诊断明确指向对应瓶颈时才进入单变量实验。

## 6. 阶段Gate

### 6.1 刚性比赛门槛

- overall Recall ≥ 0.85；
- overall FDR ≤ 0.20；
- vehicle匹配IoU=0.35；
- ship/aircraft匹配IoU=0.50；
- class-aware matching必须开启。

### 6.2 非劣和增益门槛

相对C0：

- mAP50-95下降不得超过0.002；
- aircraft F1下降不得超过0.005；
- ship或vehicle至少一个F1提升0.005；
- KD健康和部署等价性必须通过。

### 6.3 结果分支

#### A：Global-KD通过

仍需执行FAH-KD。如果FAH-KD进一步提升，FAH为主候选；否则Global-KD可进入第二seed。

#### B：Global-KD失败，FAH-KD通过

这是最有价值的创新证据：全局模仿无效，按OOF失效和比赛层级选择性传递有效。执行FAH第二seed。

#### C：两种KD都失败，但C0提升

最终采用纯YOLO或数据课程方案。报告明确说明DINOv3在当前教师/数据下无稳定收益。

#### D：mAP稳定但船车改善

如果飞机非劣、刚性门槛通过，进入Pareto比较。不能只看总mAP；同时报告船车F1、Recall和FDR。

#### E：船车改善但飞机明显下降

不晋级。降低飞机KD参与度不等于允许破坏飞机；必须重新短筛并使用同一C0。

#### F：KD loss非零但梯度证据失败

结果作废，按接线错误处理，不能称为负实验。

## 7. 服务器运行与续训

服务器完整命令位于根目录README和`scripts/`。

所有训练必须满足：

- 新run-name时目录不存在；
- 中断后从同目录`last.pt`恢复；
- 禁止用`best.pt`冒充完整续训；
- 禁止跨实验组恢复；
- 禁止自动生成`-2/-3`目录；
- 完整KD权重和`best_deploy.pt`都要保存；
- 大规模逐epoch权重默认关闭，节约磁盘。

## 8. 预计资源与时间

RTX 4090/4090D单卡粗略预算：

| 阶段 | 预计耗时 |
|---|---:|
| 环境安装和测试 | 20～60分钟 |
| 数据来源清单、硬链接划分、SHA审计 | 20～90分钟 |
| 120轮基线单seed | 2～4小时 |
| 双seed基线 | 4～8小时 |
| DINO教师30轮 | 1～2小时 |
| 教师TRAIN缓存 | 1～3小时 |
| 三组健康检查 | 10～30分钟 |
| C0+Global-KD 8轮 | 1～3小时 |
| 三折OOF 30轮 | 5～9小时 |
| FAH-KD 8轮 | 1～2小时 |
| 最终双候选长训 | 4～12小时 |
| 大图参数验收 | 1～3小时 |

不应一次性启动全部阶段。每个Gate失败都会停止后续昂贵实验。

## 11. 验收标准

项目在以下条件同时满足时视为工程验收：

1. 新服务器按README可完成环境检查；
2. 数据冻结能阻止来源数量错误和跨split精确重复；
3. B0、C0和至少一个KD候选可训练并产出权重；
4. 中断后可从`last.pt`恢复；
5. KD健康检查能识别缓存miss、分支为0和无梯度；
6. 完整权重与部署权重检测器SHA一致；
7. 评估使用车辆0.35、其他0.50和class-aware规则；
8. Gate能够给出明确晋级/淘汰结论；
9. 最终部署不加载DINOv3；
10. 结果、配置、数据版本和代码提交可追溯。

算法是否超过新基线属于实验结论，不作为伪造性工程承诺；乙方承诺的是结论可信、代码可执行和结果可复现。
